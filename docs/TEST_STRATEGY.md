# Test Strategy

## Test Pyramid

- Unit tests cover canonicalization, exact-origin path-case policies, exclusion matching, hashing, root detection, identity-transition planning, collision merging, persisted-plan parsing, content normalization, record comparison, PKCE primitives, validators, schema migrations, queue coalescing, and retry scheduling with injected clocks and randomness.
- Repository and service tests run against a faithful in-memory mock of `chrome.storage.local` and `chrome.storage.session`, including change events, error paths, large Gutenberg documents, sync-queue restart/coalescing/CAS behavior, atomic remote hydration, migration recovery from every journal phase, and shared-lock mutation exclusion.
- React component tests use React Testing Library with explicit fake timers and injected Chrome API, repository, and service dependencies to verify user-visible state, keyboard behavior, blank-canvas pointer focus and caret placement, interactive-target non-stealing, navigation, hierarchical recent-note loading/refresh/open failures, uncounted loading/error headings, full/filtered/zero/empty/retained-error ready counts, local title/path filtering, focused input, no-match feedback, two-stage Escape, navigation reset, direct serialized-block parser recognition, genuine pinned Gutenberg rich-paste conversion, safe DOM-order unsupported-structure fallback, repeated/mixed-order visible fragments, concealed subtree exclusion, malformed unsafe stored markup, root-aware selection adaptation, safe persistence projection, runtime settings version, options validation/migrations, stale-recovery-safe editor settings, BYOS configuration, Connect/Reconnect/Disconnect, exact expiry, worker credential invalidation, automatic connection follow-up, status-refresh recovery, config-less cleanup, passive per-page pending state, aggregate queue counts, and stale post-save remote-claim suppression.
- Transport and synchronization tests mock `fetch`, Chrome identity, AWS SDK request handling, local/remote repositories, clocks, and retry randomness while asserting exact OAuth form fields/scope/callback state, suspension-safe PKCE, token and credential lifetime, disconnect cancellation, connection-bound worker credential generations, path-style S3 configuration, deterministic keys/winners, tombstones, per-page pending intent, bounded per-page and whole-run retry, automatic lifecycle triggers, restart recovery, concurrent-save preservation, partial failure continuation, integrity conflicts, and redacted errors without making production requests.
- Production-package tests parse the manifest and emitted HTML/JavaScript/CSS to reject undeclared resources, external executable URLs, unsafe evaluation, actual external or inline source-map annotations, accidental credentials, unstable filenames, and missing files while ignoring inert annotation-shaped runtime strings, templates, and regular expressions. Build compatibility tests additionally require the exact pinned isolated-editor visual-editor and registry-import patterns, transform its two deprecated WordPress aliases to stable APIs, alias only the exact block/format registry entries, prove the emitted editor graph contains exactly the selected eight blocks and nine formats rather than either complete registry, enforce the exact ordered structural/component/format/supported-block stylesheet imports with required composition markers, representative unsupported-block exclusions, and maximum size budgets, fail closed on dependency drift, and preserve the existing MV3-safe Lodash rewrite. These composition audits do not assert CSS declaration values or computed appearance. Release-package tests parse the dependency-free ZIP, verify deterministic metadata/order/checksum/version binding, enforce classic-ZIP limits and physical source/output isolation, reproduce concurrent runners, freeze the audited snapshot across content and membership races, and fault every archive/checksum backup/publish/rollback/recovery/cleanup boundary without sacrificing the prior good pair.
- Playwright launches the unpacked production extension under Chromium/Xvfb. Current coverage verifies options, the runtime-derived installed version, service-worker startup, the unsupported panel state, absence of editor JavaScript and CSS requests while unsupported, lazy editor-resource requests after supported navigation followed by real typing, keyboard focus and right-aligned Settings placement, a non-overflowing writing column whose first block begins 16 pixels from the top and both sides at narrow and wide widths, a short control-free blank Gutenberg canvas that fills the space between the header and passive status at 280×720, three distinct ordinary blank-canvas clicks that each focus before typing and persist/reload their combined text, absence of the two rejected WordPress deprecation messages, real paragraph/heading/list-item focus-edit-undo behavior, native keyboard type/undo/redo, content-driven document growth without an inner editor scroller, genuine trusted `text/html` copy/paste from a normal page into headings, paragraphs, lists, quotes, code, safe inline formats, and unsupported table/figure/image source fragments with exact order and occurrence counts through live content, storage, and reload, partial-selection replacement, nested-list adaptation, supported-tab navigation, an actual Gutenberg save through panel reload and same-profile Chromium restart, the default-off then opted-in exact-origin root index, true non-root descendant boundaries, excluded same-path query and similarly prefixed sibling records, client-side filter focus/no-match/two-stage Escape, visible ready-result counts, unchanged section height and focused input viewport position while two results narrow to one and zero, a rendered editor boundary of at least 400 pixels, and canonical-new-tab opening without fatal or duplicate-store errors. Appearance is not specified through CSS-source, internal-class, or exact computed-presentation assertions; visual theme, contrast, focus treatment, native toolbar hosting, and approved live BYOS remain manual acceptance. All eight defined Chromium scenarios are runnable; there is no intentionally skipped placeholder.

## Required Gates

`npm run check` aggregates formatting, ESLint, strict TypeScript, Vitest coverage, production build, CSP/package audit, and stable browser smoke tests. `npm run release:package` repeats the production build/audits before creating the deterministic artifact and checksum. CI starts from `npm ci` under Node.js 24.18.0, runs unfiltered Vitest discovery for the complete suite, preserves the unpacked Chromium/Xvfb smoke gate, then builds exactly one release ZIP and requires its sidecar to contain exactly the independently computed archive-specific checksum before strict checksum and ZIP validation.

## Coverage Priorities

Acceptance-critical branches require direct tests: unsupported schemes; exact-origin path-case scope; path-insensitive identity equivalence with query-case preservation; global/custom exclusion scope; duplicate queries; identity collisions; addition-output-to-removal-input lifecycle; persisted migration corruption, provenance, CAS mismatch, every interruption phase, startup recovery, and concurrent mutation exclusion; unchanged saves; untouched-empty clears; tombstones; default-off exact-origin indexing, root aggregation, true descendant boundaries including stored casing variants, local filter keyboard behavior, and canonical opening; exact timestamp conflicts; expired OAuth; state mismatch; one-time secret disposal; local-newer and remote-newer reconciliation; failed upload coalescing; restart recovery; disconnect/reconnect; and missing client configuration.

## Determinism

Tests inject clock, revision ID generation, randomness, extension storage, credential provider, and transport. Browser tests use isolated persistent profiles and local fixtures, and must not depend on a live BYOS account.

## Manual Verification

Before a release candidate, load the exact audited `dist/` package into the target Chrome stable release and verify toolbar-to-panel behavior, common page navigation, narrow widths, keyboard-only editing/settings, system theme changes, trusted rich paste from another application, browser restart, offline persistence, and BYOS connection with a dedicated approved test client. Record results in orchestration state; do not replace automated coverage with this checklist.
